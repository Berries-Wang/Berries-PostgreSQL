## 1. WAL 核心思想与总览

**问题**：数据页 8KB，一次修改可能只动几十字节。如果每次修改都把整页刷盘：I/O 放大严重；且 8KB 页写入不是原子的，宕机瞬间可能写了一半（torn page），页彻底损坏。

**方案（WAL, Write-Ahead Log，预写式日志）**：修改数据页之前，先把"做了什么修改"以**紧凑的日志记录**追加到日志文件并**先于数据页落盘**。这样：

- 数据页可以长期留在内存慢慢刷（I/O 合并），崩溃后靠重放日志恢复；
- 日志采用**追加写**（顺序 I/O）+ 整页镜像兜底，回避 torn page 问题；
- 只要"日志先落盘"成立，崩溃后从最近 Checkpoint 重放日志即可恢复到宕机时刻。

**不变式**：任何一个脏数据页落盘之前，产生这页修改的 WAL 记录必须先落盘。PG 在两处强制这条规则：

1. **事务提交时**：`RecordTransactionCommit()` 先 `XLogFlush()` 刷 WAL，成功后才改 CLOG 标记提交（`access/transam/xact.c:1498-1508`）；
2. **Buffer 写盘时**：Buffer 管理器写页前检查页上 LSN 是否已刷盘（`XLogNeedsFlush`，由 `BufferSync` 调用），没刷就先刷 WAL。

**总览图：一条 UPDATE 的 WAL 全旅程**（各步骤详见后续章节）：

## 2. 磁盘形态：段文件、页与记录格式

### 2.1 段文件与文件名

WAL 落在 `pg_wal/`（PG10 以前叫 `pg_xlog`，书中旧称，见 §15）下，默认按 **16MB 一段**切分：

- 段大小：`DEFAULT_XLOG_SEG_SIZE (16*1024*1024)`，`include/pg_config_manual.h:20`；实际运行值 `wal_segment_size`（`access/transam/xlog.c:144`），initdb 时 `--wal-segsize` 可选 1MB~1GB；
- 文件名 24 个字符：`TLI(8) + Log(8) + Seg(8)`，由 `XLogFileName()` 生成（`access/xlog/xlog_internal.h:165-171`，`snprintf("%08X%08X%08X", tli, logSegNo / XLogSegmentsPerXLogId, logSegNo % ...)`）；
- 页大小 `XLOG_BLCKSZ` 默认 8192，编译期由 configure 决定（`configure.ac:337-339`）。

```text
 pg_wal/ 目录
 ┌─────────────────────────────────────────────────────────────────┐
 │  0000000100000000000000A1      ← 24 字符段文件名                  │
 │  ┌─ TLI 时间线 00000001   (xlog_internal.h:165)                  │
 │  ├─ Log 段号高 32 位 00000000                                    │
 │  └─ Seg 段号低 32 位 000000A1  (= 161 * 16MB 处的绝对偏移)        │
 │  0000000100000000000000A2                                      │
 │  0000000100000000000000A3                                      │
 │  00000002.history              ← 时间线历史文件 (新时间线fork点)  │
 │  0000000100000000000000A1.00000028.backup  ← 基准备份起点记录     │
 │  archive_status/               ← 归档状态: *.ready / *.done      │
 └─────────────────────────────────────────────────────────────────┘
```

### 2.2 段文件的页布局

每个段文件按 8KB 分页，**每页开头有页头**（跨页续写的记录靠它定位），段内第一页用长页头额外记录系统标识和段大小：

### 2.3 记录格式


- 记录链由 `xl_prev` 形成**双向链**（前向指针），因为从"记录结束位置"（提交 LSN）回溯时只能向回找；
- 跨页记录：后续页头 `xlp_rem_len` 标明续接，读取端据此拼接（`XLogDecodeNextRecord`，`access/transam/xlogreader.c:529`）；
- 单条记录上限 `XLogRecordMaxSize = 1020MB`（`xlogrecord.h:74`）。

### 2.4 pg_control：恢复的"地图"

控制文件 `global/pg_control`（`include/catalog/pg_control.h`）保存恢复起点：

- `checkPoint`：最近一次 checkpoint 记录的 LSN（`pg_control.h:133`）；
- `checkPointCopy`：最近 CheckPoint 结构本体（`pg_control.h:35-65`，含 `redo` 字段——重放从此开始）；
- `state`：`DB_SHUTDOWNED / DB_SHUTDOWNED_IN_RECOVERY / DB_IN_PRODUCTION / ...`，启动时据此判断是否需要崩溃恢复；
- 写入方：`UpdateControlFile()`（`access/transam/xlog.c:4582`），读入方 `ReadControlFile()`（:4344）。

所有运行时状态集中在共享内存结构 `XLogCtlData`（`access/transam/xlog.c:451-555`），`XLOGShmemInit()`（:4956）创建。**读这张图后再看任何 WAL 函数都不会迷路**：

**锁分工**（WAL 高并发设计的精髓——锁越细，插入越并行）：

| 锁 | 保护对象 | 持有时间 |
|---|---|---|
| `insertpos_lck` 自旋锁 | CurrBytePos/PrevBytePos（预留空间） | 几条指令 |
| 8 把 `WALInsertLocks` | 标识"有插入进行中"+ FPW 状态 | 一条记录的拷贝期 |
| `WALBufMappingLock` | WAL 缓冲页的换入换出 | 初始化一个新页 |
| `WALWriteLock` | 段文件的实际写/刷（全局唯一写者） | 一次 XLogWrite |
| `info_lck` 自旋锁 | LogwrtRqst/asyncXactLSN 等元信息 | 瞬时 |
| `ControlFileLock` | pg_control 的读写 | 瞬时 |

**LSN 的三种"位面"**：`CurrBytePos` 是"可用字节"计数（把所有页头剔除后的连续空间），通过 `XLogBytePosToRecPtr()`（xlog.c:1861）换算成真实物理 LSN——这样预留空间只需 `CurrBytePos += size`，自旋锁内不用算页头跨越。

### 4.1 调用入口（以 heap_insert 为例）


各索引/DDL 路径同理（btree 用 `RM_BTREE_ID` 等）；全新页可直接用 `log_newpage()`（xloginsert.c:1143）一次登记整页。资源管理器 ID 总表见 `include/access/rmgrlist.h:28-49`。

### 4.2 XLogInsert：组装 + 插入的调度

`XLogInsert()`（xloginsert.c:474）主体是个 **do-while 重试环**（:504-525）：

1. `GetFullPageWriteInfo(&RedoRecPtr, &doPageWrites)`（xlog.c:6507）读全局 FPW 状态——此时还没拿插入锁，读到的可能过期；
2. `XLogRecordAssemble()` 组装记录链（:520 → :548）；
3. `XLogInsertRecord()` 真正插入（:523 → xlog.c:748）；
4. 若插入时发现"FPW 刚被打开/RedoRecPtr 前进了，而这页没打镜像"→ 返回 `InvalidXLogRecPtr`，**整体重新组装**（xlog.c:848-858 的重试路径）。

### 4.3 XLogRecordAssemble：整页镜像（FPW）判定

FPW 是 WAL 机制对抗 torn page 的核心：**checkpoint 之后第一次被修改的页，把整页内容塞进 WAL 记录**。这样恢复时可以直接用镜像覆盖坏页，之后增量的 redo 才是安全的。判定逻辑（xloginsert.c:604-626）：

```text
 对每个登记的 buffer:
 ┌────────────────────────────────────────────────────────────────────┐
 │ REGBUF_FORCE_IMAGE ?          → needs_backup = true     :605-606   │
 │ REGBUF_NO_IMAGE ?             → needs_backup = false    :607-608  │
 │ !doPageWrites (FPW 关且无备份)? → needs_backup = false    :609-610  │
 │ 否则:                                                              │
 │   needs_backup = (PageGetLSN(page) <= RedoRecPtr)        :618-620  │
 │   ── 页上次修改发生在 checkpoint redo 点之前                        │
 │   ── 说明 checkpoint 尚未把它刷盘, 磁盘上是"旧页", 崩溃后           │
 │      重放从 redo 点开始, 必须先有整页镜像打底                       │
 │   若不需要备份: 记录 *fpw_lsn = min(*fpw_lsn, page_lsn)  :621-625   │
 │     (供 XLogInsertRecord 锁内复核是否要重来, 见 §5)                 │
 └────────────────────────────────────────────────────────────────────┘
 needs_backup 为真时:
   1) REGBUF_STANDARD 页: 计算 hole_offset/hole_length 剔除空闲区间
      (pd_lower~pd_upper 之间的空洞不进 WAL)      xloginsert.c:658-683
```

## 5. 流程二：并发插入协议（XLogInsertRecord）

## 8. 流程五：Checkpoint

### 8.1 触发来源

checkpointer 进程（postmaster/checkpointer.c:182）在主循环里等三类触发（:376-396）：

1. **显式请求**：`RequestCheckpoint()`（checkpointer.c:1003）设置 `ckpt_flags`（:376-380）——来源包括 SQL `CHECKPOINT`、`pg_ctl stop`（shutdown checkpoint）、恢复完成（end-of-recovery）、归档超时等；

### 9.4 读侧：预读（recovery_prefetch）

重放是"读一条 → 应用一条"的串行逻辑，但读 WAL 文件可以提前。PG15+ 引入预读器（`recovery_prefetch` 默认 `try`，guc_tables.c:5357）：

- `ReadRecord()`（xlogrecovery.c:3162）→ `XLogPrefetcherReadRecord()`（xlogprefetcher.c:981）；
- 预读器维护 `LsnReadQueue`（lrq，:245 起），按 `wal_decode_buffer_size`（默认 512KB）为窗口，`XLogPrefetcherNextBlock`（:459）提前发起异步读；
- **过滤机制**：`XLogPrefetcherAddFilter/IsFiltered`（:856/:914）——当记录即将修改的页还没被重放到（filter 命中），预读才有意义；页一旦被重放就该失效 filter（`XLogPrefetcherCompleteFilters` :894）。预读的收益恰恰是：**重放等页时，页已经在内核页缓存里了**；
- 文件从哪来：`XLogPageRead`（xlogrecovery.c:3329）→ `WaitForWALToBecomeAvailable`（:3586）按 `XLOG_FROM_ARCHIVE → XLOG_FROM_PG_WAL → 流复制` 的优先级找段（:3598-3627），`XLogFileReadAnyTLI`（:4328）跨时间线尝试；
- 解码与校验：`XLogDecodeNextRecord`（xlogreader.c:529）→ 页头校验 `XLogReaderValidatePageHeader`（:1235，魔数 0xD118 不对即报损坏）→ `ValidXLogRecordHeader`（:1138）/`ValidXLogRecord`（:1204，验 CRC 与 xl_prev 链）→ `DecodeXLogRecord`（:1684）。

## 11. 与复制/热备的衔接

（详细协议另立文档，此处只列 WAL 机制的接触点）

- **walsender**：从 WAL 缓冲/文件读日志流式发送（PG18 新增 `WALReadFromBuffers`，xlog.c:1751，让物理 walsender 直接读**尚未写出**的 WAL 缓冲页，降低复制延迟）；
- **walreceiver（备库）**：收到的 WAL 写入本地 pg_wal 并 flush；startup 进程重放（§9）；
- **同步复制**：本地 XLogFlush 后，`SyncRepWaitForLSN`（syncrep.c:148）按 `synchronous_commit` 档位（`off/local/remote_write/on/remote_apply`）等备库 ACK：`remote_write` 等备库写入、`on` 等备库 flush、`remote_apply` 等备库重放完成（xact.c:1557，`SyncRepWaitMode` 限制 :185-187）；
- **minRecoveryPoint**：备库读数据页前的不变式——页 LSN 不能超过已重放位置，由 `UpdateMinRecoveryPoint`（xlog.c:2700）在 XLogFlush 路径上推进（§6.2 :2793-2797）；
- **FPW 与备份**：`pg_backup_start` 期间 `runningBackups > 0` 强制 FPW（xlog.c:846），保证基础备份页 + 后续 WAL 可拼出一致副本（书 §10.7.2 的原理）。

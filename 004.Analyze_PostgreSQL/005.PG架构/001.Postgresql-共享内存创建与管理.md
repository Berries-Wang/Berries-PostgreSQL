### 2.1 平台层：PGSharedMemoryCreate（默认 mmap 路径）

`shared_memory_type` 默认值由编译期宏决定：非 EXEC_BACKEND 的 Unix = `mmap`（include/storage/pg_shmem.h:76）；EXEC_BACKEND（Windows/Cygwin）= SysV（:78）。

 │    huge_pages=on/try 时:                                                     │

**段头（每个 PG 段的第一块内容）**——`PGShmemHeader`（include/storage/pg_shmem.h:29-42）：

| 字段 | 作用 |
|---|---|
| `magic`(:31) | 679834894，识别"这是 PG 的段"（崩溃识别用） |
| `creatorPID`(:33) | 创建进程 |
| `totalsize` / `freeoffset`(:34-35) | arena 总量/已切分到哪 —— 分配器全部状态 |
| `dsm_control`(:36) | DSM 控制段句柄（孤儿段清理时顺藤摸瓜删 DSM） |
| `index`(:37) | ShmemIndex 哈希表指针 |
| `device` / `inode`(:39-40) | 归属哪个 DataDir（同名多实例互不误删） |

## 3. 运行期管理：arena 分配器

主段内部是一个**只增不减的 bump 分配器**（shmem.c 头注释 :57-63 明说"分配了就不能归还"）：

```text
 主共享内存段 (一次 mmap 的大块)
 ┌────────────────────────────────────────────────────────────────┐
 │ PGShmemHeader │ ShmemLock │ ShmemIndex(HTAB) │ 各子系统结构体…   │
 │ freeoffset ──────────────────────────┘▲                        │
 └───────────────────────────────────────┼────────────────────────┘
 ShmemAllocRaw (shmem.c:186)  每次分配的全部逻辑:
   ① size = CACHELINEALIGN(size)  :203     ← 缓存行对齐(防伪共享)
   ② SpinLockAcquire(ShmemLock)   :208     ← 全段唯一一把自旋锁 (临界区只有加法!)
   ③ newStart = freeoffset; freeoffset += size  :210-216   空间不够 → NULL → ERROR
   ④ SpinLockRelease              :221
 没有 free(): 子结构自己管自己 (如哈希表自由链 :57-60 注释);
 想看切了什么 → SELECT * FROM pg_get_shmem_allocations();  shmem.c:491
   (返回 name/offs/size, 是观察 arena 的官方窗口; NUMA 版 :548, 见 §9)

 ShmemInitStruct("名字", size, &found)   shmem.c:387 —— 子系统入驻协议:
   到 ShmemIndex(名为 "Shmem Index" 的哈希表, InitShmemIndex :283 建)
   按【字符串名字】查: hash_search(..., HASH_ENTER_NULL, &found)  :429
   ├─ 没找到: ShmemAlloc 切一块 + 登记名字→地址   found=false (postmaster 首次启动)
   └─ 找到: 直接取地址                            found=true  (EXEC_BACKEND 子进程重建指针)
   —— 名字是跨进程认址的机制: fork 场景其实用不上(直接继承指针),
      它主要为 EXEC_BACKEND 和调试/审计存在 (shmem.c:50-55 注释)
```

子系统侧的样子（以 XLOG 为例）：`XLOGShmemInit()` 里 `ShmemInitStruct("XLOG Ctl", …)`——38 个子系统的入驻清单就是 `CreateOrAttachShmemStructs`（ipci.c:268）里的那串调用，与 `CalculateShmemSize` 的求和项一一对应（**改一处必须同步另一处**，这是源码里两份列表的对应关系）。

## 4. 子进程如何共享

```text
 Linux 默认 (fork 模型):
   postmaster mmap 完成后, 每次 fork_process:
     内核复制子进程的 VMA(虚拟地址区间) → 指向同一匿名共享映射
     【零系统调用、零拷贝、零重附着】—— 指针值(ShmemBase 等)直接继承
   所以: InitShmemAccess/各 ShmemInitStruct 的 found=true 分支
         在 Linux 上只有 postmaster 崩溃重启时会走

 EXEC_BACKEND (Windows/Cygwin, 无 fork 继承):
   子进程 SubPostmasterMain → PGSharedMemoryReAttach (sysv_shmem.c:890)
     从 mini SysV 段头读回主段地址/大小 → mmap 回同一地址
   各子进程重跑 CreateOrAttachShmemStructs 重建本地指针 (ipci.c:253-265 注释)
   DSM 段: dsm_backend_startup (dsm.c:423) 重附着控制段
```

## 5. DSM 动态共享内存

主段是启动时定死的；**运行期按需再开的段**走 DSM（并行查询、pg_dsm 扩展、临时大对象等）。PG16+ 还有按名字跨会话共享的 DSM Registry（storage/ipc/dsm_registry.c，`DSMRegistryShmemInit` ipci.c:282——注册表本身在主段里）。

```text
 DSM 设施全景 (启动期两件事 + 运行期 create/attach)
 ┌───────────────────────────────────────────────────────────────────────┐
 │ 启动: dsm_postmaster_startup (dsm.c:177)  ← ipci.c:243                  │
 │   建【控制段】(记录所有活着的 DSM 段的 handle/引用计数/pin 状态),          │
 │   句柄写进主段头 hdr->dsm_control —— 崩溃后下一个 postmaster 能顺藤删干净  │
 │   dynamic_shared_memory_type=mmap 时还要 dsm_cleanup_for_mmap :192/:320 │
 │ 启动: dsm_shmem_init (dsm.c:479)  ← CreateOrAttachShmemStructs :281     │
 │   若 min_dynamic_shared_memory>0: 在【主段内】预留一块 (ShmemInitStruct   │
 │   "Preallocated DSM" :487), 交给 FreePageManager 按页管理 :499           │
 │   → 小 DSM 段直接从主段切, 零系统调用!                                   │
 │                                                                        │
 │ 运行: dsm_create (dsm.c:516)                                           │
 │   ① 主区域还有空闲页? → 从 FreePageManager 切 (make_main_region_dsm_    │
 │      handle :1262), 无系统调用                                          │
 │   ② 不够/太大 → dsm_impl_op (dsm_impl.c:159) 按后端实现发系统调用:       │
 │      POSIX(默认): shm_open("/PostgreSQL.<pid>") :259                    │
 │                  → ftruncate 定长 :396 → mmap(MAP_SHARED, fd) :315     │
 │                  → close(fd) (段名仍占着, 断开靠 munmap, 销毁 shm_unlink :237)│
 │      SysV:  shmget(IPC_PRIVATE) :509 → shmat :571                      │
 │              (attach 后立刻 shmctl(IPC_RMID) :543 —— 名字先删,           │
 │               段随最后一个 shmdt 消失, 不留孤儿)                          │
 │      mmap 文件: pg_dynshmem/ 下建文件 open :831 → 零填充 :885 →          │
 │              mmap :918 (EXEC_BACKEND 平台用)                            │
 │ 运行: dsm_attach(handle)  (dsm.c:665)                                  │
 │   并行查询: leader 把 handle 放进启动消息 → worker 进程 dsm_attach 同一段  │
 └───────────────────────────────────────────────────────────────────────┘
 为什么 DSM 不塞进主段: 主段尺寸 postmaster 启动时定死(改参数要重启);
 DSM 段独立生命周期(查询结束即回收), 还能被 pin 住跨会话存活。
```

## 6. 销毁与崩溃重启

| 场景 | 路径 | 系统调用 |
|---|---|---|
| 正常关闭 | on_shmem_exit 回调链（ipci.c 注册的各清理 + AnonymousShmemDetach sysv_shmem.c:675 / IpcMemoryDelete :298） | `munmap`(:680)；SysV 模式 `shmctl(IPC_RMID)`(:300)+`shmdt`(:289) |
| 子进程退出 | 各自 `munmap` 自己附着的 DSM；主段映射随进程消亡（fork 出的映射引用计数减一，最后一个进程退出时内核才真正回收页） | `munmap` |
| postmaster 崩溃 | 页由内核回收（匿名映射无名字，进程全死=段消失）；mini SysV 段留孤儿 → 新 postmaster 启动时识别并 `shmctl(IPC_RMID)`（§2.2），DSM 孤儿段靠 `hdr->dsm_control` 清（dsm.c:238） | `shmctl` |
| postmaster 重启恢复流程 | `shmem_exit(1)` → `LocalProcessControlFile(true)` → `CreateSharedMemoryAndSemaphores()`（postmaster.c:3202 一带） | 重跑 §2 全流程 |

## 7. 信号量

`PGReserveSemaphores(numSemas)`（ipci.c:232）与共享内存同一入口创建。Linux 默认走**无名 POSIX 信号量**（backend/port/posix_sema.c）：

- `sem_init(sem, 1, 1)`（posix_sema.c:137，pshared=1 跨进程）——glibc 底层是 **futex**；等待 `sem_wait`（:326）、唤醒 `sem_post`。
- 用途：LWLock 等待队列的睡眠/唤醒（每后端一个信号量，PGPROC 里）。
- 备选：SysV（sysv_sema.c，`semget/semop`，EXEC_BACKEND 平台）。
- **自旋锁不走这里**：TAS 是一条 x86 指令（`lock; xchgb`，include/storage/s_lock.h:131-134 内联汇编），纯用户态原子操作，无系统调用。

## 8. 系统调用总表

按"PG 代码点 → libc → Linux syscall → 内核里发生了什么"组织，供结合内核源码（mm/ipc 子系统）逐一对照：

| # | libc/syscall | PG 调用点 | 用途 | 内核侧入口/关键结构 |
|---|---|---|---|---|
| 1 | `mmap(NULL, size, PROT_READ\|PROT_WRITE, MAP_SHARED\|MAP_ANONYMOUS[, MAP_HUGETLB], -1, 0)` | sysv_shmem.c:622/:646（主段）；dsm_impl.c:918（文件段） | 创建主共享段 / DSM mmap 文件段 | `ksys_mmap`→`vm_mmap_pgoff`；匿名+共享 → `shmem_zero_setup` 挂 tmpfs inode；建 VMA(`vm_area_struct`, `VM_SHARED`)；**不分配物理页** |
| 2 | `munmap(addr, len)` | sysv_shmem.c:680/:986；dsm_impl.c 各 DETACH | 摘除映射 | `vm_munmap`→`unlink_vmas`；页缓存引用计数减一 |
| 3 | `shmget(key, size, IPC_CREAT\|IPC_EXCL)` | sysv_shmem.c:156/:783；dsm_impl.c:509 | SysV 段创建（主段兜底 / mini 名牌段 / DSM sysv 模式） | `newseg()`：`kern_ipc_perm`+`shmid_kernel`，配额受 `/proc/sys/kernel/shm*` 限制（PG 9.3 弃用的原因，书 §7.1.9） |

## 9. Linux 内核学习地图

按 syscall 给出学习入口（内核函数名以 6.x 为参考）：

```text
 mmap(MAP_SHARED|MAP_ANONYMOUS) 的内核路径 ── PG 主段的本质
 ┌──────────────────────────────────────────────────────────────────────┐
 │ sys_mmap → vm_mmap_pgoff → mmap_region()                             │
 │   MAP_ANONYMOUS|MAP_SHARED → shmem_zero_setup():                      │
 │     内核【偷偷创建一个匿名 tmpfs 文件】(shmem_kernel_file_setup)        │
 │     —— "匿名共享内存"其实是挂在 tmpfs 上的文件映射, 只是没有路径名        │
 │   只建 VMA(vm_area_struct, VM_SHARED|VM_MAYSHARE), 不分配物理页         │
 │                                                                       │
 │ fork(): copy_process→dup_mmap 复制子进程 VMA 链 → 指向同一 tmpfs 文件   │
 │   ★ 共享映射不做 COW: 页表项两边都指向同一物理页                         │
 │   → PG 的 fork 继承 = 子进程看到的 ShmemBase 与父进程逐字节相同          │
 │                                                                       │
 │ 首次写: 缺页异常 handle_mm_fault → do_shared_fault → shmem_get_folio   │
 │   → 伙伴系统分配物理页, 挂进 tmpfs inode 的页缓存(XArray)               │
 │   → 之后任何进程访问同一偏移都命中同一页 —— "共享"的实现                  │
 │   (页分配是全局一次, 不是每进程一次; smaps 里算 Shared_Dirty)           │
 │                                                                       │
 │ OOM/回收: tmpfs 页只进 swap 不进回收(无 backing 文件),                 │
 │   所以 shared_buffers 不会被动缺页(除非 swap) —— 对比普通文件页          │
 └──────────────────────────────────────────────────────────────────────┘

 与 SysV IPC 的对照 (PG 9.2 前的主段实现):
   shmget/shmat 建的段, 内核里同样是"内部 tmpfs 文件 + VMA" (ipc/shm.c);
   差别是生命周期管理: SysV 有全局名字空间+系统级配额(shmmni/shmmax),
   孤儿段要人工 ipcs/ipcrm —— 这正是 PG 换 mmap 的动机 (书 §7.1.9)
   mmap 匿名段: 无名字无配额, 进程全死内核自动回收; PG 用 mini-SysV 段
   自己补上了"身份识别"这一块 (§2.2)

 POSIX shm_open: 显式使用 /dev/shm 这个 tmpfs 挂载点
   (= 内核自动挂载的 shmem), 与 SysV 无关, 与匿名 mmap 同族
   PG 的 DSM 默认实现走这里, ls /dev/shm 可见 PostgreSQL.<pid> 文件

 大页两条路线 (PG 只用第一条):
   ① MAP_HUGETLB: 从启动预留池(hugetlbfs)拿 2M/1G 页, PG 主段方式
   ② madvise(MADV_HUGEPAGE): THP 透明大页, 内核自动聚合 —— PG 不调用
   学习点: TLB miss 率、伙伴系统迁移类型(MIGRATE_MOVABLE/CMA)
 NUMA (PG18 新增观察工具, 不做绑定):
   move_pages(2) 查询页分布; pg_numa_touch_mem_if_required 先触碰再查
   (pg_numa.h:28) —— 对应内核 mm/mempolicy.c
```

## 10. 观察与实验

```sql
-- PG 侧
SHOW shared_memory_type;      -- mmap (默认) / sysv
SHOW huge_pages;              -- try (默认)
SHOW huge_pages_status;       -- 启动后可查: on/off
SELECT * FROM pg_get_shmem_allocations() ORDER BY size DESC LIMIT 10;  -- arena 切分
SELECT pg_size_pretty(sum(size)) FROM pg_get_shmem_allocations();
-- PG18: SELECT * FROM pg_get_shmem_allocations_numa(); (需编译时 libnuma)
```

```bash
# OS 侧 (把 §2 的代码点对着看)
cat /proc/$(head -1 $PGDATA/postmaster.pid)/smaps_rollup | grep -E 'Shared|Rss'   # 共享页计费
grep -B1 -A12 'rw-s' /proc/<postmaster_pid>/maps | head -30   # MAP_SHARED 区间与 /dev/zero
pmap -X <postmaster_pid> | head    # 主段是最大的一块常驻
ipcs -m                            # mmap 模式只见 mini 段(~56B); sysv 模式见整段
ls -la /dev/shm/ | grep PostgreSQL # 运行期 DSM (posix) 段; 并行查询时会闪现
ls $PGDATA/pg_dynshmem/            # EXEC_BACKEND 平台才有内容
cat /proc/meminfo | grep -i huge   # HugePages_Total/Free (预留池)
```

实验建议：① 开 `log_checkpoints` 观察 `min_dynamic_shared_memory` 生效前后并行查询是否还闪现 `/dev/shm` 文件；② `huge_pages=on` 但不预留大页 → 启动失败信息即 §2.1 的回退逻辑反例；③ 对比 `shared_memory_type=sysv` 时 `ipcs -m` 的输出差异。

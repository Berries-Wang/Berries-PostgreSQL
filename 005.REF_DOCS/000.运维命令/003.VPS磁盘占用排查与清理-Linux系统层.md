# VPS 磁盘占用排查与清理（Linux 系统层）

> 适用场景：磁盘占用**逐步上涨**、不知道被什么吃掉。
> PostgreSQL 数据库内部（表膨胀/WAL/复制槽）的分析见 [001.磁盘空间分析-优化-释放](001.磁盘空间分析-优化-释放.md)，本文覆盖系统层。
> 排查原则：先用 `df`/`du` 定位大头，再对症清理，**不要盲目 rm**。

## 1. 五分钟定位大头

```shell
# 各挂载点使用率
df -h

# 从根目录逐层往下钻，找出大目录（-x 不跨文件系统，避免误入挂载点）
sudo du -xh --max-depth=1 / 2>/dev/null | sort -rh | head -15
# 对最大的目录继续钻，例如：sudo du -xh --max-depth=1 /var | sort -rh | head

# 交互式排查神器（推荐安装）
sudo apt install -y ncdu && sudo ncdu -x /

# ⚠️ df 显示 90% 但 du 找不到大文件？→ 有"已删除但仍被进程持有"的文件
sudo lsof +L1 | awk '$7 > 104857600' | sort -k7 -rn   # 列出 >100MB 的已删除文件
# 处置：重启持有文件的进程（常见是 rsyslog / 应用日志），比重启机器快
sudo systemctl restart rsyslog
```

## 2. 常见增长源逐项排查

### 2.1 PostgreSQL（有 PG 的 VPS 优先查这三样）

```shell
PGDATA=$(sudo -u postgres psql -Atc "SHOW data_directory;")
LOGDIR=$(sudo -u postgres psql -Atc "SHOW log_directory;")   # 可能是相对路径，相对 $PGDATA

# ① WAL 堆积（复制槽/归档卡住，逐步上涨的头号嫌疑）
sudo du -sh "$PGDATA/pg_wal"
sudo -u postgres psql -c "SELECT slot_name, active, wal_status FROM pg_replication_slots;"

# ② PG 服务器日志暴涨（logging_collector=on 且没有轮转清理策略时）
sudo du -sh "$LOGDIR" 2>/dev/null || sudo du -sh "$PGDATA/$LOGDIR"

# ③ 表膨胀/死元组（业务持续写入时缓慢增长，属正常但需要治理，见 001 文档）
sudo -u postgres psql -d shopfi_saas -c \
  "SELECT relname, n_live_tup, n_dead_tup FROM pg_stat_user_tables ORDER BY n_dead_tup DESC LIMIT 5;"
```

> 若 `logging_collector = off`，PG 日志走 stderr 进 journald → 看下一条 2.2。

### 2.2 systemd journal（不知不觉涨到几个 G 的常客）

```shell
journalctl --disk-usage                       # 看占用
sudo journalctl --vacuum-size=200M            # 立即压到 200M
sudo journalctl --vacuum-time=7d              # 只保留 7 天

# 永久限制：/etc/systemd/journald.conf 加/改
#   SystemMaxUse=200M
sudo systemctl restart systemd-journald
```

### 2.3 apt 缓存 / 旧内核（Ubuntu、Debian）

```shell
sudo du -sh /var/cache/apt
sudo apt clean                       # 清 /var/cache/apt/archives 的 deb 包
sudo apt autoremove --purge          # 旧内核 + 不再需要的依赖
dpkg -l | grep -E 'linux-image-[0-9]' | wc -l   # 看留了几个内核
```

### 2.4 Docker（装了 docker 的机器，经常是最大头）

```shell
docker system df                                  # 镜像/容器/卷/缓存各占多少
sudo du -xh --max-depth=1 /var/lib/docker | sort -rh   # overlay2/containers/volumes 细分

docker image prune -a        # 删除未被容器使用的镜像
docker container prune       # 删除已停止的容器
docker volume prune          # 删除未挂载的卷（⚠️ 确认没有要保留的数据卷）
docker builder prune         # 构建缓存
# 慎用一键版：docker system prune -a --volumes
```

### 2.5 /var/log 与应用日志

```shell
sudo du -sh /var/log/* 2>/dev/null | sort -rh | head -15
ls -lh /var/log/postgresql/ 2>/dev/null          # Debian 系 PG 包的日志在这里

# 轮转策略检查（是否配置了 rotate + compress + delaycompress）
cat /etc/logrotate.conf
sudo logrotate -d /etc/logrotate.conf            # dry-run 看会不会执行

# 大日志立即释放（⚠️ 用 truncate 清空，不要 rm——rm 会让空间直到进程重开文件才释放）
sudo truncate -s 0 /var/log/某个暴涨的.log
```

### 2.6 旧备份 / dump / 迁移脚本残留

```shell
# 全盘找 >100MB 的 sql/dump/压缩包（xdev 不跨文件系统）
sudo find / -xdev \( -name "*.sql" -o -name "*.dump" -o -name "*.gz" -o -name "*.tar*" \) \
  -size +100M -exec ls -lh {} \; 2>/dev/null

# 常见残留位置
sudo du -sh /root /home /tmp /var/tmp /opt 2>/dev/null
```

### 2.7 core dump / crash 报告

```shell
sudo du -sh /var/crash /var/lib/systemd/coredump 2>/dev/null
# systemd-coredump 占用大时：
sudo coredumpctl list | tail
sudo journalctl --vacuum-size=100M   # coredump 存在 journald 里，同 2.2 清法
```

### 2.8 snap 旧版本（Ubuntu）

```shell
sudo snap set system refresh.retain=2    # 只保留 2 个版本
# 清理已禁用的旧 revision（默认保留 3 个，每个都是完整拷贝）
sudo sh -c 'rm -rf /var/lib/snapd/snap/*/*/ 2>/dev/null'  # 谨慎；或用 snapcraft 社区脚本
sudo du -sh /var/lib/snapd
```

### 2.9 邮件队列（cron 报错堆积时会长）

```shell
sudo du -sh /var/spool/postfix /var/spool/mail /var/mail 2>/dev/null
sudo postqueue -p 2>/dev/null | tail -5      # 有 postfix 的话看队列
```

## 3. 找出"谁在增长"：记录增速

逐步增长的问题，一次性 `du` 看不出元凶，要记录**增速**：

```shell
# 每天快照各关键目录大小，肉眼对比哪条在涨
sudo tee /usr/local/bin/disk-snapshot.sh >/dev/null <<'EOF'
#!/bin/bash
echo "===== $(date '+%F %T') ====="
df -h | grep -vE 'tmpfs|udev|overlay'
du -xsh /var/lib/postgresql /var/log /var/lib/docker /var/cache/apt 2>/dev/null
EOF
sudo chmod +x /usr/local/bin/disk-snapshot.sh

# 挂 cron：每天 08:00 记录
( sudo crontab -l 2>/dev/null; echo '0 8 * * * /usr/local/bin/disk-snapshot.sh >> /var/log/disk-snapshot.log' ) | sudo crontab -

# 事后分析：找出"最近 1 天内变动过的大文件"（正在增长的文件会现形）
sudo find / -xdev -type f -size +50M -mmin -1440 -exec ls -lh --time-style=long-iso {} \; 2>/dev/null
```

## 4. 一键体检脚本

```shell
sudo tee /usr/local/bin/disk-check.sh >/dev/null <<'EOF'
#!/bin/bash
echo "===== 磁盘概览 ====="
df -h | grep -vE 'tmpfs|udev'
echo; echo "===== /var 大头 ====="
du -xh --max-depth=1 /var 2>/dev/null | sort -rh | head -8
echo; echo "===== journal ====="
journalctl --disk-usage 2>/dev/null
echo; echo "===== >200MB 的文件 TOP15 ====="
find / -xdev -type f -size +200M -exec ls -lh {} \; 2>/dev/null | sort -k5 -rh | head -15
echo; echo "===== 已删除但仍被持有的文件 ====="
lsof +L1 2>/dev/null | awk 'NR==1 || $7 > 104857600'
EOF
sudo chmod +x /usr/local/bin/disk-check.sh
sudo /usr/local/bin/disk-check.sh
```

## 5. 长效预防（清理一次不如管住增长）

| 措施 | 配置 |
|---|---|
| journald 上限 | `journald.conf: SystemMaxUse=200M` |
| 日志轮转 | 应用日志接入 logrotate（weekly + rotate 4 + compress） |
| PG WAL 兜底 | `max_slot_wal_keep_size = '20GB'`，废弃复制槽及时删 |
| PG 日志轮转 | `log_rotation_age=1d` + `log_truncate_on_rotation=on`（按天命名） |
| 大表空间治理 | 按时间分区，老分区定期 DROP（见 001 文档 4.7） |
| Docker | 定时 `docker system prune -f` 的 cron/systemd timer |
| 备份管理 | dump 按日期命名 + `find -mtime +7 -delete` 定期清旧备份 |
| 告警 | cron 检查使用率超 80% 时告警（邮件/webhook） |

```shell
# 简单磁盘告警 cron（每小时检查根分区）
( sudo crontab -l 2>/dev/null; \
  echo '0 * * * * [ $(df --output=pcent / | tail -1 | tr -dc 0-9) -ge 80 ] && echo "disk >80% on $(hostname)" | mail -s "disk alert" you@example.com' ) | sudo crontab -
```
